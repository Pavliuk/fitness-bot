# 🏋️ Fitness Bot — Telegram фітнес-тренер

Telegram-бот на **aiogram 3** для планування тренувань, контролю виконання,
харчування та прогресу.

## Функціонал

- **Реєстрація**: стать, вік, вага, зріст, ціль (схуднення / набір маси / витривалість), рівень підготовки
- **Планування тренувань**: генерація програми на 4–8 тижнів з ротацією вправ по тижнях
- **База вправ**: назва, опис, м'язова група, посилання на відео/GIF (`assets/exercises.json`)
- **Контроль виконання**: чекліст на день, відмітка «виконано», лог підходів/повторень/ваги
- **Нагадування**: тренування, вода, прийоми їжі, сон (APScheduler); час кожного
  нагадування налаштовується індивідуально, а «тихі години» (за замовчуванням
  23:00–07:00) вимикають усі сповіщення вночі, крім самого нагадування лягати спати
- **Харчування**: щоденник калорій/БЖУ, орієнтовна денна норма (формула Міффліна-Сан Жеора)
  та персональна база продуктів (БЖУ на 100 г) з автопідрахунком за кількістю грамів
- **Прогрес**: кількість виконаних вправ, історія зміни ваги

## Технічний стек

- Python 3.12+, [aiogram 3](https://docs.aiogram.dev/) (async, FSM для анкет)
- SQLAlchemy 2.0 (async ORM) + SQLite (легкий перехід на PostgreSQL)
- Alembic (версійні міграції БД)
- APScheduler (нагадування за розкладом)
- Docker / docker-compose

## Структура проєкту

```
fitness-bot/
├── bot/
│   ├── handlers/        # start, workout, nutrition, progress, reminders
│   ├── keyboards/       # inline/reply клавіатури
│   ├── states/          # FSM для анкет
│   ├── database/        # моделі, engine, шар доступу до даних (requests.py)
│   ├── services/        # генератор планів тренувань, розрахунок калорій
│   ├── scheduler/       # нагадування (APScheduler)
│   ├── leadgen/         # пошук потенційних клієнтів у публічних Telegram-групах
│   │   └── connectors/  # каркаси під офіційні API Facebook/Instagram/TikTok
│   └── config.py
├── alembic/             # міграції БД
├── assets/              # статичні дані, що йдуть в образ (НЕ монтуються volume'ом)
│   ├── exercises.json   # база вправ
│   └── media/           # мотиваційне відео тощо
├── data/                # runtime-стан: fitness.db, сесія лідогенерації (монтується volume'ом)
├── scripts/
│   └── leadgen_login.py # одноразовий вхід у Telegram user-сесію лідогенерації
├── .env.example
├── requirements.txt
├── docker-compose.yml
├── Dockerfile
└── main.py
```

## Крок 1. Отримати токен бота у @BotFather

1. Відкрий Telegram і знайди [@BotFather](https://t.me/BotFather).
2. Надішли команду `/newbot`.
3. Вкажи ім'я бота (відображуване, будь-яке) — наприклад `Fitness Coach`.
4. Вкажи унікальний username бота, що закінчується на `bot` — наприклад `my_fitness_coach_bot`.
5. BotFather надішле токен у форматі `123456789:AA...`. Скопіюй його — він знадобиться у `.env`.
6. (опційно) командою `/setdescription` та `/setuserpic` налаштуй опис і аватар бота.

## Крок 2. Локальний запуск без Docker

```bash
git clone <URL_вашого_репозиторію>
cd fitness-bot

python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# Відкрий .env і встав свій BOT_TOKEN

python main.py
```

При першому запуску бот сам створить `data/fitness.db` (SQLite) та наповнить
таблицю вправ даними з `assets/exercises.json`.

## Крок 3. Запуск через Docker

```bash
cp .env.example .env
# Встав свій BOT_TOKEN у .env

docker compose up -d --build
docker compose logs -f      # переглянути логи
docker compose down         # зупинити
```

Папка `data/` монтується як volume, тому база даних зберігається між
перезапусками контейнера. Статичні файли (`assets/exercises.json`, медіа)
навмисно лежать поза `data/` — інакше порожній volume при першому
монтуванні (наприклад, на Railway) стирає їх, бо перекриває вміст
директорії з образу.

## Перехід на PostgreSQL

1. Додай у `requirements.txt` драйвер `asyncpg`.
2. Зміни `DATABASE_URL` у `.env` на:
   ```
   DATABASE_URL=postgresql+asyncpg://user:password@localhost:5432/fitness_bot
   ```
3. Онови `sqlalchemy.url` у `alembic.ini` на той самий рядок (без `+aiosqlite`).
4. Згенеруй і застосуй міграції:
   ```bash
   alembic revision --autogenerate -m "init"
   alembic upgrade head
   ```

Код моделей і хендлерів залишається без змін — це і є сенс шару SQLAlchemy ORM.

## Логіка генерації плану тренувань

Для кожної пари (ціль × рівень) визначено шаблон тижня — які дні тижня
тренувальні та на які групи м'язів. Вправи вибираються з `assets/exercises.json`
і **ротуються по тижнях** (кожен новий тиждень зсуває вибірку вправ у межах
групи м'язів), щоб програма не була одноманітною. Логіка — у
`bot/services/workout_generator.py`, легко розширюється новими шаблонами.

## 🎯 Модуль лідогенерації (пошук потенційних клієнтів)

Окремий модуль у `bot/leadgen/`, що моніторить **публічні** Telegram-групи/
канали за ключовими словами й повідомляє адміністратора бота про збіги —
наприклад, хтось у міській групі "оголошень" написав «шукаю майстра з
ремонту» — і бот одразу присилає це повідомлення з посиланням.

**Це окремий Telegram-бот**, не той самий, що фітнес-тренер. Один код
(`main.py`) вміє запускатись у двох режимах через `BOT_MODE`:

| `BOT_MODE` | Що вмикається |
|---|---|
| `fitness` (за замовчуванням) | реєстрація, тренування, харчування, прогрес, нагадування — жодних команд лідогенерації |
| `leadgen` | лише `/kw_add`, `/src_add`, `/leads` тощо — жодної фітнес-анкети |

Тобто для лідогенерації потрібен **другий бот у @BotFather** (свій
`BOT_TOKEN`) і **окремий деплой** з `BOT_MODE=leadgen` — використання
одного й того самого бота для обох ролей не підтримується навмисно, щоб
не змішувати фітнес-клієнтів з адмінськими командами пошуку лідів.

### Що модуль робить і чого свідомо НЕ робить

- ✅ Слухає нові повідомлення лише в тих публічних каналах/групах, які ви
  самі додали командою `/src_add` і до яких акаунт-монітор сам приєднався.
- ✅ Дані — лише те, що люди самі публічно написали в цих групах.
- ❌ НЕ читає приватні чати/особисте листування будь-кого, включно з власним
  акаунтом-монітором.
- ❌ НЕ скрейпить Facebook / Instagram / TikTok напряму — це порушує їхні
  умови використання. Замість цього в `bot/leadgen/connectors/` лежать
  каркаси під офіційні API цих платформ (див. нижче).

### Технічна причина окремої Telegram-сесії

Bot API (звичайний токен від @BotFather) не дозволяє боту самостійно
приєднуватись до публічних груп і не показує йому історію/нові повідомлення
в чатах, куди його явно не додали адміном. Тому моніторинг веде окремий
Telegram-акаунт через **Telethon** (MTProto user-сесія) — це той акаунт,
яким ви самі вирішуєте, до яких публічних спільнот приєднуватись.

### Налаштування (окремий деплой, окремий `.env`/набір змінних на хостингу)

1. У @BotFather створіть **другого, окремого бота** (наприклад
   `MyLeads_bot`) — саме його `BOT_TOKEN` піде в цей деплой.
2. Встановіть `BOT_MODE=leadgen`.
3. Отримайте `API_ID` і `API_HASH` на https://my.telegram.org → *API
   development tools*.
4. Дізнайтесь свій Telegram user id (напр. через [@userinfobot](https://t.me/userinfobot))
   і впишіть його як `ADMIN_IDS` (через кому, якщо їх декілька).
5. Заповніть `TG_API_ID`, `TG_API_HASH`.
6. Виконайте одноразовий вхід (запитає номер телефону й код із Telegram):
   ```bash
   python scripts/leadgen_login.py
   ```
   Файл сесії збережеться в `data/leadgen_session.session` — для локального
   запуску цього достатньо, `main.py` підключиться до нього без повторних
   запитів. Скрипт також виведе base64-рядок цієї сесії — знадобиться на
   кроці деплою на хостинг (`TG_SESSION_B64`, див. розділ Railway нижче).
7. Запустіть бота і в чаті з новим `MyLeads_bot` (як адмін з `ADMIN_IDS`)
   виконайте:
   ```
   /kw_add шукаю майстра з ремонту
   /src_add @назва_публічної_групи
   ```
   і перезапустіть бота, щоб моніторинг приєднався до нового джерела.

### Команди (тільки для `ADMIN_IDS`)

| Команда | Опис |
|---|---|
| `/leads_help` | Довідка по модулю |
| `/kw_add <фраза>` / `/kw_list` / `/kw_del <id>` | Керування ключовими словами |
| `/src_add <@username або посилання>` / `/src_list` / `/src_del <id>` | Керування джерелами |
| `/leads [N]` | Останні N знайдених лідів |

Щодня о 9:00 (`TIMEZONE`) бот також надсилає короткий дайджест за добу.

### Підключення Facebook / Instagram / TikTok

За вашою відповіддю офіційного бізнес-доступу поки немає на жодній з цих
платформ — тому зараз реалізовано лише Telegram. У `bot/leadgen/connectors/`
є готові каркаси (`facebook.py`, `instagram.py`, `tiktok.py`) з описом, який
саме офіційний API потрібен і що він реально дозволяє (жодна з платформ не
дає стороннім застосункам пошук чужих постів/чатів "за будь-якими ключовими
словами" без спеціального дозволу):

- **Facebook/Instagram** — [Meta Graph API](https://developers.facebook.com/)
  після App Review: коментарі/згадки під вашими власними сторінками,
  Marketing API для реклами, Hashtag Search API для Instagram (обмежено).
- **TikTok** — [TikTok for Developers](https://developers.tiktok.com/): Business
  API для вашої реклами/акаунта, Research API (окрема заявка, зазвичай для
  дослідницьких організацій).

Коли отримаєте доступ до котроїсь із них, реалізуйте `fetch_matches()` у
відповідному файлі — інтеграція з рештою модуля (збереження `Lead`,
сповіщення, `/leads`) вже готова й не залежить від платформи.

## Деплой на Railway

Репозиторій містить `railway.json` (builder = `Dockerfile`, restart on failure),
тому деплой — це підключити GitHub-репозиторій і виставити змінні середовища.

Фітнес-бот і лідогенерація — це **два окремих Telegram-боти** (див. розділ
про `BOT_MODE` вище), тож і на Railway це **два окремих сервіси**, обидва
задеплоєні з того самого репозиторію/гілки `main`, але з різними змінними.

### Сервіс 1 — фітнес-бот (`GymTrack24_bot` і т.п.)

1. https://railway.app → **Sign in with GitHub**
2. **New Project → Deploy from GitHub repo** → оберіть `fitness-bot`, гілку `main`
3. **Variables**: `BOT_TOKEN` (токен фітнес-бота), `BOT_MODE=fitness` (або не
   вказувати — це значення за замовчуванням)
4. **Settings → Volumes → New Volume**, mount path `/app/data` — інакше
   `data/fitness.db` зникатиме при кожному передеплої

### Сервіс 2 — лідогенерація (окремий бот, напр. `MyLeads_bot`)

1. У тому ж Railway-проєкті: **New → GitHub Repo** → знову `fitness-bot`,
   гілка `main` (це другий, незалежний сервіс)
2. **Variables**: `BOT_TOKEN` (токен ДРУГОГО бота), `BOT_MODE=leadgen`,
   `ADMIN_IDS`, `TG_API_ID`, `TG_API_HASH` — та бажано окремий
   `DATABASE_URL` (напр. `sqlite+aiosqlite:///./data/leadgen.db`), щоб не
   ділити файл БД із фітнес-сервісом
3. **Settings → Volumes → New Volume**, mount path `/app/data` — тут
   зберігається `leadgen.db`
4. `TG_SESSION_B64` — Telethon-логін інтерактивний (код із SMS) і не може
   пройти прямо в контейнері Railway, тому виконайте локально:
   ```bash
   python scripts/leadgen_login.py
   ```
   і вставте виведений ним base64-рядок у цю змінну повністю. Бот сам
   розпакує його у файл сесії при старті — жодних маніпуляцій із volume
   через CLI не потрібно.

Обидва сервіси деплояться автоматично після пуша в `main`; логи кожного —
у його вкладці **Deployments → View Logs**.
